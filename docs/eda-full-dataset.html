Verdict

Research freely. Do not train the submission on it yet.

44,446 − 38,617 = 5,829, which is exactly the number of unlabelled images in the assignment's official test set. This release is the official training subset plus the test items, with their labels attached.

Fitting anything on these rows before the official test IDs are quarantined would put evaluation images inside training, and every score afterwards would be meaningless. data/test/styles_prediction.csv — the authoritative list of those 5,829 IDs — is currently missing from the working tree and must be restored first.

01
Provenance

What arrived, and why the arithmetic matters

Four artefacts landed under data/train/. Read together they describe the complete Myntra catalogue, not a training split — the directory name is now misleading.

The release ships a metadata table, a URL index, a directory of full-resolution JPEGs and a directory of per-item JSON documents. The four agree with one another almost perfectly: every metadata row has a URL record and a JSON record, and no image file exists without a metadata row. The only asymmetry is five rows whose image never downloaded.

The problem is not integrity, it is scope. The assignment defines a labelled training set of 38,617 rows and a held-out test set of 5,829 unlabelled images. This table has 44,446 rows, and the difference is exactly 5,829. The five missing image IDs are the same five the assignment subset is missing, which confirms the subset was carved out of this same source.

That makes the file a legitimate research resource and an illegitimate training set. Its labels can validate the taxonomy, quantify how rare a class really is, and reveal what the 60×80 downscale destroyed. What they cannot do is contribute a gradient step to a model whose score is later reported against the official test images.

A dataset that answers the exam is not a bigger training set. It is a different experiment. Why this report exists

Integrity

Three defects a default parser hides

Every count here comes from reading the raw bytes with missing-value conversion switched off, so a literal NA stays distinct from an empty field.

Found by measuring, not by reading the docs
  1. Twenty-two rows are wider than the header

    The header names ten fields, but 20 rows carry eleven and 2 carry twelve, because product names such as “Brand Shirt, Blue” contain unquoted commas. pandas.read_csv raises ParserError on line 6,044 and refuses the file outright. The audit helper now captures the surplus as Overflow: columns and rebuilds the product name in memory, so no row is dropped and no column is shifted.

  2. “NA” is a value, not a gap

    usage holds the literal string NA in 316 rows and is genuinely empty in exactly 1. A default read collapses both into NaN, silently merging a real category with a real gap. In the assignment subset this affected 71 rows; here it is 4.5× larger and impossible to ignore.

  3. Blanks are few, and target-specific

    Only 23 cells in the entire table are empty: 21 in season, 1 in year, 1 in usage. A row blank for one target is still perfectly usable for the other three, so dropping rows wholesale would discard good labels.

  4. Five labels point at nothing

    IDs 12347, 39401, 39403, 39410 and 39425 have metadata, a URL and a JSON document, but no JPEG. The URL index still lists them, so this is a download gap rather than a catalogue gap — and it is inherited unchanged by the assignment subset.

Seventeen more articleType classes appear here than in the assignment subset, and almost all of the growth is in the tail: classes holding fewer than ten images went from 33 to 35, and six classes still hold exactly one. Adding 15% more data did not thin the tail, it lengthened it — so the tail is a property of the catalogue, and any rare-class policy has to be argued from the data rather than assumed away.

The hierarchy is also not clean. 25 articleType labels map to more than one masterCategory or subCategory, so merging rare classes “up the hierarchy” is not a mechanical operation — for those 25 labels the hierarchy itself is ambiguous. And with masterCategory spanning Personal Care (2,404 rows), Free Items, Sporting Goods and a single Home item, “season” and “gender” do not mean the same thing across rows: a fragrance has no season in the sense a coat does.

Pixels

13.9 GiB, sampled rather than swallowed

Decoding 44,441 multi-megapixel JPEGs inside an interactive notebook is a waste of an hour. File coverage is checked exhaustively; pixel properties come from a fixed-seed sample of 512 files, which estimates the population and proves nothing about the other 43,929.

Two sizes dominate and every sampled file is RGB — no grayscale, unlike the assignment subset, where 343 images decode as single-channel L. All four sampled sizes share the same 3:4 aspect ratio, so a fixed-size resize will not distort anything.

The practical consequence is cost, not quality. At 324× the pixel budget of a 60×80 thumbnail, decoding dominates training time long before the model does. Resize inside the data loader, or materialise one deliberately documented cache — never a second uncontrolled copy of the catalogue.

Legitimate

Understanding what the downscale destroyed

Fine texture is what separates Formal from Casual. Comparing a full-resolution crop against its 60×80 counterpart shows whether that signal survives at all — an argument the report can make with evidence instead of assertion.

Uses labels for analysis, not for fitting

Legitimate

Sizing the rare-class problem honestly

Six singletons and 35 classes under ten images, measured on 15% more data, show the tail is a property of the catalogue rather than of the sampling. That justifies whichever rare-class policy the report defends.
