# Task 4 evidence

Generated by `notebooks/task-4/01_v1_eda.ipynb`.

- `external_provenance.json` records source hashes, counts, missing files, decode
  status, and the no-new-split interpretation.
- `external_reconciliation.csv` and `external_split_coverage.csv` prove ID and
  canonical-split coverage.
- `external_geometry_summary.csv` uses development rows only.
- `same_id_agreement.csv` is a fixed 256-row development sample comparing each
  teacher image with its V1 copy.

The bulky decode audit and variant index are rebuildable local files under
`data/processed/task4/` and remain outside Git.

## Frozen retrieval protocol coverage

`retrieval_protocol_coverage.csv` is generated by
`notebooks/task-4/05_task4_visual_search.ipynb` from development folds only. It
contains one row per protocol and K value:

- `protocol`: `primary` for Protocol A or `family` for Protocol B.
- `k`: the Protocol A cutoff, or the family-positive availability threshold.
- `total_queries`: all eligible fold-`1` queries considered.
- `scored_queries`: queries with at least one possible positive.
- `excluded_queries`: queries omitted because their metric is undefined.
- `zero_strict_queries`: queries with no grade-2 or eligible family positive.
- `fewer_than_k_strict_queries`: queries with fewer than K strict positives.

For Protocol B, the K=`5` and K=`20` rows are availability and coverage
diagnostics only. Protocol B retrieval scoring remains frozen at K=`10`:
Recall@10, Hit Rate@10, and Precision@10.

The notebook writes this tracked file through `fashion.config.ROOT`, so its
location is always exactly
`results/evidence/task4/retrieval_protocol_coverage.csv`.

## Frozen image preprocessing

Milestone 3 compares `60×80`, `96×128`, and `240×320` with the fixed
development-only HSV-and-edge probe:

- `preprocessing_comparison.csv` contains fold, source direction, protocol,
  metric, quality, tie, and cost rows.
- `preprocessing_size_selection.csv` records the equal teacher/V1 same-source
  nDCG@10 selection and selects `96×128`.
- `preprocessing_stability.csv` records all five held-out folds for the top two
  sizes.
- `preprocessing_robustness.csv` records clean, wide, and tall query quality and
  Top-10 overlap.
- `preprocessing_contract.json` records the selected RGB/LANCZOS letterbox
  contract and local-cache manifests.
- `preprocessing_normalization_fold1.json` contains teacher and V1 RGB
  statistics fitted from the 26,217 fold-1 training products only.

The tracked evidence contains no holdout pixels or outcomes. The lossless
development caches remain local below `data/processed/task4/preprocessing/`.
