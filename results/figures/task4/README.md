# Task 4 figures

The V1 audit figures below are generated by
`notebooks/task-4/01_v1_eda.ipynb`.

- `external_geometry.png` shows development-only dimensions, aspect ratios, and
  compressed file sizes.
- `same_id_agreement.png` shows paired teacher/V1 agreement and storage cost.
- `teacher_v1_pair_examples.png` shows fixed dHash-agreement quantiles, not
  hand-picked examples.
- `retrieval_protocol_overview.png` shows the frozen fold-1 query/gallery roles and
  scorable-versus-excluded query coverage at K=10.
- `preprocessing_comparison.png` compares same-source quality, cross-source
  robustness, and measured preprocessing cost for the three candidate sizes;
  its title distinguishes the frozen `240×320` contract from the `96×128`
  probe winner. Rebuild it with `scripts/task4/run_preprocessing.py`.
- `baseline_examples.png` shows all eight selected development-only baseline
  examples: one normal success plus grayscale, unusual-geometry, canvas,
  weak-family, rare-type, rare-type-colour, and unavailable-family cases. Each
  row has one query and five V1 results. Rebuild it with
  `scripts/task4/run_baseline.py`.

## `final/` — figures cited by the final comparison report

`results/reports/task4-model-comparison.html` displays nine figures from
`final/`. Rebuild all of them with `scripts/task4/generate_report_figures.py`
(no training, no GPU); the run is deterministic and byte-reproducible. Every
value is read from the strict freeze bundle
`results/evidence/task4/final/task4-final-comparison.json` plus hash-checked
evidence artifacts, and the generator refuses any image whose
`data/processed/splits.csv` row is not `development`.

- `method_quality_comparison.png` — same-source and cross-source nDCG@10 for
  R1–R5, B1, the three untrained descriptors, and the random floor.
- `cost_quality_tradeoff.png` — quality against CPU batch-one p95 latency, with
  index size and trained parameter panels.
- `stability_folds.png` — the R5 and R3 five-fold points with mean and ±1 SD.
- `gallery_policy_comparison.png` — teacher-only, V1-only and two-view policies
  on quality, latency and index storage.
- `failure_slice_profile.png` — the pre-registered slices as a Protocol A
  nDCG@10 and Protocol B Recall@10 heatmap per method.
- `canvas_robustness.png` — clean/wide/tall canvas quality and Top-10 overlap.
- `r5_retrieval_success.png`, `r5_retrieval_failure.png` — five best and five
  weakest development queries with the frozen index's exact Top-10, bordered by
  graded relevance.
- `r5_retrieval_slices.png` — one query and its Top-5 for each pre-registered
  slice, including the wide-canvas failure drawn on the canvas the model saw.

The report also keeps its inline, labelled HTML/SVG charts, and reads the six
learned manifests, ten stability records, canonical deployment/gallery JSON,
gallery timing, and failed run-registry rows. Everything is development-only;
the holdout remains sealed.
