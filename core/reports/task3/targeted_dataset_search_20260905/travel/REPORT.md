# Travel dataset search — 5 September 2026

No source in this search is ready to supply clean, independent **item-level Usage=Travel** labels. Fashion32 has real Travel **outfit** labels. Bag datasets mostly label the object, not its use. Do not turn every backpack, handbag, or duffel into Travel.

The parent search covers Amazon and FashionStylist separately. This note covers nine other releases/leads. No teacher labels, training, or split files were touched. No images were downloaded or visually inspected, so no image-quality claim is made. Independence from teacher images remains untested for every candidate below.

## Best next leads

**1. Garments2Look / Mytheresa: inspect product metadata next, as a weak proxy only.** The author release includes real catalog items alongside synthetic outfits. Its supplement shows the native product type `bags::travel bags`; this is a bag type, not a Usage label. A 65,536-byte HTTP range sample of `mytheresa_image_v1.0_2512.json` confirms fields `source`, `gender`, `type`, `name`, `images.product.full`, `images.product.partial`, `official_description`, `description`, and `main_category`. The sampled beginning contains baby bibs, not travel bags, so no matching bag count was verified. Full product metadata is 120,158,369 bytes and was not downloaded. The source separates original merchant descriptions from other descriptions. Next: use a larger bounded metadata pass to count only requested bag families with explicit original travel purpose/type and retain the evidence text. Inspect matching product images and run hash checks before any intake. [Author repository](https://github.com/ArtmeScienceLab/Garments2Look), [publisher dataset](https://huggingface.co/datasets/ArtmeScienceLab/Garments2Look), [supplement](https://openaccess.thecvf.com/content/CVPR2026/supplemental/Hu_Garments2Look_A_Multi-Reference_CVPR_2026_supplemental.pdf).

Access: public HF files; viewer is broken because it relies on a dataset script. Licence: publisher card declares Apache-2.0; underlying merchant-image rights are not separately established here. Do not count its Polyvore branch as independent of other Polyvore releases. Its 80K pairs are publisher-reported, not an eligible bag count.

**2. Fashion32 / FashionRec: useful evidence about context, unsuitable as direct bag labels.** The original paper reports 1,706 Travel outfits, 447 Home outfits, over 40K items and 152 fine categories. Those are paper counts. The author download page returned a web error; direct HTTPS failed certificate verification. No bypass was attempted. [Original paper](https://arxiv.org/abs/1912.06227), [author-hosted paper](https://www.larry-lai.com/doc/arXiv2019_Fashion.pdf), [author page](http://www.larry-lai.com/fashion.html).

The public FashionRec derivative provides an auditable metadata route. I downloaded the 20,402,093-byte `outfits_lite.parquet`. It has **103,283 outfits**, including **13,981 Fashion32 rows**, of which **1,724 have `occasion="旅行"` (Travel)**. All 1,724 have blank `categories`; these cannot establish bag support. The version/count difference from the original paper is unresolved. Five exact examples and the full occasion count are in `fashionrec_metadata_audit.json`. Crucially, publisher code copies `Outfit_Occasion` onto each item and then deduplicates items by image MD5, keeping the first occurrence. Thus even an item table's nonempty `occasion` is an inherited outfit label, not an independent item annotation. A bag may appear in several contexts. [Metadata](https://huggingface.co/datasets/Anony100/FashionRec/resolve/main/meta/outfits_lite.parquet), [schema](https://huggingface.co/datasets/Anony100/FashionRec/blob/main/meta/README.md), [construction code](https://huggingface.co/datasets/Anony100/FashionRec/blob/main/construct_parquet.py).

Access: public metadata and image/dialogue tar files; item metadata is over 43MB and was not fetched. Example image paths are local paths on the publisher's machine and their `url` fields are empty; they are not usable image links. Licence: no explicit dataset licence was found in the reviewed FashionRec card or Fashion32 page. Next: only revisit for an outfit-context study after rights and actual item-to-image access are clear. Do not add these as item Usage labels. FashionRec and Fashion32 are one source family, not two independent sources.

## Exclusions and lower-priority sources

**Bag6k / CBDet.** Author reports 6,505 video frames and 21,457 object boxes. Exact categories are `backpack`, `satchel`, `trolley case`, `tote bag`. These are multi-object street/station/mall frames, not isolated product labels. Public Google Drive/Baidu links exist; no archive was fetched. Repository has MIT but a separate licence for source network-video images is not established. Exclude for Travel usage; possible object detection research only. [Author release](https://github.com/jsjxyjl/CBDet).

**shravya11 luggage-bags-dataset.** Publisher card describes 148 annotated suitcase images, 816 unannotated luggage images, 785 unannotated handbags, 795 unannotated backpacks, and 2,535 designer-handbag examples. The claimed 5,079 total differs from viewer's 2,683 rows, so counts are not a file audit. Label `suitcase` and designer model names do not establish Travel. Public HF access; CC-BY-4.0 is claimed, but web-harvested image provenance/rights are not established. Exclude: it cannot solve this without new labels. [Publisher card](https://huggingface.co/datasets/shravya11/luggage-bags-dataset).

**NewLuggageDataset.** Publisher reports 29,053 images with `backpack`, `bag`, `trolley`; training includes three augmented variants per image. It is surveillance object detection, not 29,053 independent product examples. Public Roboflow route is linked, but no download/auth test was done. README claims MIT; upstream image rights unresolved. Exclude for Usage labels. [Author release](https://github.com/CostiCatargiu/NewLuggageDataset).

**DataCluster suitcase/luggage.** Publisher page contradicts itself with 3,000+, 6,000+, and 7,000+ counts. Full access requires contacting sales, which this task forbids. No clear data licence verified. Exclude regardless of count: luggage detection has no Travel usage label. [Publisher repository](https://github.com/datacluster-labs/Suitcase-Luggage-Dataset-Indoor-Object-Image).

**MVB (Multi-View Baggage).** Original authors report 4,519 baggage identities and 22,660 airport images, with identity/material labels. Actual airport use is contextual evidence but still not the teacher's catalog Usage annotation. Images come from baggage-handling and checkpoint cameras. No primary current download or data licence was verified. Exclude for direct intake; no need to chase third-party training repos. [Original paper](https://arxiv.org/abs/1907.11366).

**LVIS.** Instance segmentation includes fine bag object concepts, but no Usage=Travel annotation was established. It shares COCO images and is not independent of COCO-based bag subsets. The official dataset endpoint returned 404 here; the author API repo exists. Exclude for the same object-type/usage mismatch. [Author API](https://github.com/lvis-dataset/lvis-api), [project](https://www.lvisdataset.org/).

## Audit limits and intake rule

About 20.6MB of saved dataset metadata/code was fetched, plus a temporary 21.5MB DuckDB reader wheel; no bulk images. The reader was isolated from the project environment. `inspect_fashionrec.py` recomputes the exact metadata counts. No raw author code was executed. No new human annotation is needed to reach the current conclusion.

Any future intake must preserve source/item identity, original purpose evidence and licence; reject duplicate hashes against **all teacher roles** without reading protected labels; group sibling views/near duplicates; use the project's canonical split contract. Native item Travel labels, native travel-bag type, marketing travel text, and outfit Travel labels must remain separate evidence classes. No count here is a count of approved new training examples.
